# Virtual Human PoC — 霜降銀座コホート リアルタイム監視

仮想人格12名（駒込・霜降銀座を中心に半径15km圏に居住）の **今この瞬間** の
位置・行動・収支を、Tokyoの実時刻（Asia/Tokyo）と実路線を使って監視するツール。

未来のシミュレーションは行いません。各人の生活は **スケジュール（時間帯テーブル）**
として定義され、ブラウザは現在時刻を読んで該当する区間を表示するだけです。

## クイックスタート

```bash
cd experiments/virtual-human
python3 monitor.py                      # ターミナルに現状表示 + out/monitor.html を生成
python3 monitor.py --at 18:30           # 任意の時刻にして検証（デバッグ用）
python3 monitor.py --date 2026-05-18    # 月曜日として観測
python3 monitor.py --no-cli             # HTML のみ生成
```

`out/monitor.html` をブラウザで開くと、毎秒更新の地図モニタが立ち上がります。

## 監視できること

### 地図表示（Leaflet / OpenStreetMap dark）

- **固定マーカー**: 霜降銀座（金）・Riverbed in Otherworld（橙）・各勤務先（灰）
- **動的マーカー**: 12名を異なる色で現在位置にプロット。
  滞在中は静止、移動中はパルスアニメーション
- **移動軌跡**: 過去30分の経路を点線で表示（電車は線路に沿って動く）
- **来店ハイライト**: RIO に居る人はマーカー拡大＋オレンジ枠

### 右パネル

ヘッダーで JST 時刻を秒単位表示。`過去を見る` スライダーで当日の過去時刻に
スクラブ可能（未来には進めない）。

カードごとに：
- 現在の **行動**（💤 睡眠中 / 🌙 夜勤勤務中 / 🚃 電車移動中 / ⭐ Riverbed で食事 …）
- 現在の **場所**
- 現在の **移動モード** と進捗（電車62%到着まで など）
- **本日の収入・支出・残高**（今この瞬間までの累積）

### 集計

- 就寝中 / 勤務中 / 霜降銀座滞在 / RIO 来店 の人数
- コホート累計の収入・支出（今までに発生した分のみ）

## 実装

| ファイル | 役割 |
| --- | --- |
| `geo.py` | 霜降銀座からの距離計算 |
| `places.py` | 実 POI（駒込病院・大手町・渋谷・川口工場 等）の lat/lng |
| `routes.py` | Tokyo 主要駅の座標と路線ポリライン（山手線・京浜東北・田園都市・三田・南北 等） |
| `persona.py` | Traits（年齢・職業・年収・性格・嗜好）と State（現金） |
| `personas.py` | 12名の人格定義 |
| `schedules.py` | 1日の時間帯テーブル（人格 × 平日/週末 × 夜勤シフト） |
| `web_export.py` | スケジュールから HTML を組み立て |
| `monitor.py` | CLI + HTML 出力エントリポイント |

## スケジュール仕様（`schedules.Segment`）

```python
Segment(
  start_min=420,         # 07:00
  end_min=450,           # 07:30
  activity="train",      # 表示用ラベル
  mode="train",          # stay / walk / train / bus / car
  place_name="山手線 駒込→東京",
  waypoints=[駒込, 田端, 西日暮里, ..., 東京],  # 区間内で線形補間
  cost_jpy=220,
  wage_jpy=0,            # 区間全体での収入額
  touchpoint=None,       # マーケ接点 {"channel": ..., "brand": ...}
)
```

ブラウザは現在分 `t` から該当 Segment を線形検索し、movement の場合は
`(t - start) / (end - start)` の比率でポリライン上を補間して位置を出します。

## 通勤・移動手段の表現

| モード | 表示 | 例 |
|---|---|---|
| `stay` | 滞在中 | 自宅・職場で動かない |
| `walk` | 🚶 徒歩 (5km/h 程度) | 駅→自宅、駅→職場 |
| `train` | 🚃 電車 | 山手線、京浜東北線、田園都市線、三田線、京浜東北 等 |
| `bus` | 🚌 バス | （未使用、拡張余地） |
| `car` | 🚗 車 | 中村の市場仕入れ、井上の工場通勤 |

電車区間は実駅座標をポリラインで結んでいるため、地図上で線路に沿って
マーカーが動きます（駒込→田端→西日暮里→... と山手線が辿られる）。

## 既知の単純化

- 1日 = 単一スケジュール（前後日の影響は考慮しない）
- 駅間補間は等時間（実際の駅間所要時間は加味していない）
- 天気・気温は当日固定（時間変動なし）
- 商店街/RIO の営業時間は人格スケジュール側で表現（実営業日と一致確認要）
- ペルソナ間相互作用なし（家族が同行する場面は森のみ手動定義）

## 拡張候補

1. **勤務表 API 連携**: 山本・井上の夜勤/日勤を実ロスターから取得
2. **天気 API**: tenki.jp / OpenWeather で実天気を反映し、雨なら屋内行動を増やす
3. **GTFS-RT**: JR/メトロのリアルタイム遅延を反映
4. **Claude API**: 行動の選択肢に微小な揺らぎを LLM で生成（外食 vs 自炊の決定など）
5. **N=100 自動生成**: 国勢調査の年齢・職業・所得分布から自動サンプリング
